Mailing lists

The mailing lists are where the Apache Hop community happens: questions get answered, proposals get discussed and decisions get made, all in public and in the archive.

Not sure which one? Use users@. It has the most people reading it, and questions about using Hop belong there rather than on dev@.

  • Users

    users@hop.apache.org

    Questions about using Hop: how to do something, why a pipeline behaves the way it does, which transform fits your problem.

    If you are not sure which list you want, this is the one.

    SubscribeBrowse the archiveUnsubscribe

  • Developers

    dev@hop.apache.org

    Development of Hop itself: design discussions, releases, votes and project decisions.

    Decisions that matter to the project are taken here, in public and on the record.

    SubscribeBrowse the archiveUnsubscribe

  • Commits

    commits@hop.apache.org

    Automated notifications of every change to the code, the website and the issue tracker.

    High volume and read-only in practice. Subscribe only if you want the firehose.

    SubscribeBrowse the archiveUnsubscribe

How subscribing works

  1. Send an empty mail to the subscribe address — the buttons above open one for you.
  2. You will get a confirmation request back. Reply to it, again with an empty mail.
  3. That is it. You are subscribed, and you can post by writing to the list address.

You do not need to subscribe to read: every list is public and fully searchable in the Apache archives.

Posting etiquette

  • Send plain text, not HTML

    HTML mail is much more likely to be caught as spam and rejected, and it reads badly in the archives that other people will search later.

  • Ask on the list, not in private mail

    An answer in the archive helps the next person with the same question. Private mail to a committer helps exactly one person.

  • Include enough to reproduce

    Hop version, operating system, what you ran, what happened and what you expected. A pipeline that shows the problem is worth several paragraphs of description.

  • Search first

    The archives go back to the start of the project, and a great many questions have been answered already.

Everything here is covered by the ASF code of conduct.
